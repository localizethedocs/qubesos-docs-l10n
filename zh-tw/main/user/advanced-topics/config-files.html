警告

此頁面適用於進階使用者。

Qubes 特定的 VM 組態檔

這些檔案放置在 /rw 中，該目錄在 VM 重新啟動後仍會保留。這樣一來，它們可以用來自訂單個 VM，而不是基於相同範本的所有 VM。這裡的腳本都以 root 身分執行。

  • /rw/config/rc.local - 在 VM 啟動時執行的腳本。適合用來變更一些服務設定、將組態檔替換為儲存在 /rw/config 中的副本等。腳本需要設定可執行權限才能被執行。使用範例：

    # Store bluetooth keys in /rw to keep them across VM restarts
rm -rf /var/lib/bluetooth
ln -s /rw/config/var-lib-bluetooth /var/lib/bluetooth

    # Add entry to /etc/hosts
echo '127.0.0.1 example.com' >> /etc/hosts

  • /rw/config/rc.local.d/*.rc - 在 VM 啟動時、緊接在 /rw/config/rc.local 之前執行的腳本

  • /rw/config/rc.local-early.d/*.rc、/rw/config/rc.local-early - 與 /rw/config/rc.local 類似的腳本，但在系統啟動序列中更早執行— 就在 sysinit.target 之前，並設定網路。

  • /rw/config/qubes-ip-change-hook - 在 NetVM 中每次外部 IP 變更和「硬體」連結狀態變更後執行的腳本。

  • 在 ProxyVM（或已啟用 qubes-firewall 服務的應用程式 qube）中，放置在以下目錄中的腳本將在啟動時按列出的順序執行，然後接著執行 qubes-firewall-user-script。適合用來編寫自訂防火牆規則。

    /etc/qubes/qubes-firewall.d
/rw/config/qubes-firewall.d
/rw/config/qubes-firewall-user-script

  • /rw/config/suspend-module-blacklist - 要在系統進入睡眠前卸載的模組列表（每行一個）。此檔案僅在用於附加了 PCI 裝置的 VM。適用於有問題的裝置驅動程式。

  • 在 NetVM/ProxyVM 中，放置在 /rw/config/network-hooks.d 中的腳本將在設定 Qubes 介面組態時執行。對於每個腳本，command、vif、vif_type 和 ip 會作為參數傳遞（請參閱 /etc/xen/scripts/vif-route-qubes）。例如，考慮一個 IP 為 10.137.0.100、以 sys-firewall 作為 NetVM 的PV 應用程式 qube work。假設其 Xen 網域 ID 為任意值 12，則 sys-firewall 中位於 /rw/config/network-hooks.d/hook-100.sh 的以下腳本：

    #!/bin/bash

command="$1"
vif="$2"
vif_type="$3"
ip="$4"

if [ "$ip" == '10.137.0.100' ]; then
    case "$command" in
        online)
            ip route add 192.168.0.100 via 10.137.0.100
            ;;
        offline)
            ip route del 192.168.0.100
            ;;
    esac
fi

    將在啟動 work 時使用參數 online vif12.0 vif 10.137.0.100 執行。請注意，在 HVM 的情況下，腳本將被呼叫兩次——一次使用 vif_type vif，然後使用 vif_type vif_ioemu``（以及不同的介面名稱）。只要 ioemu 介面存在，就應該優先使用（由掛鉤腳本決定）。當 VM 決定使用 PV 介面（vif_type ``vif）時，ioemu 介面將被拔除。

請注意，腳本需要是可執行的（chmod +x）才能被使用。

另請參閱 bind-dirs 了解如何在應用程式 qube中輕鬆修改任意系統檔案並使這些變更持久保存的說明。

dom0 中的 GUI 與音訊組態

GUI 組態檔 /etc/qubes/guid.conf 是少數不受 qubes-prefs 或 Qubes Manager 工具管理的檔案之一。樣本組態（包含在預設安裝中）：

# Sample configuration file for Qubes GUI daemon
#  For syntax go https://www.hyperrealm.com/libconfig/libconfig_manual.html

global: {
  # default values
  #allow_fullscreen = false;
  #override_redirect_protection = true;
  #allow_utf8_titles = false;
  #secure_copy_sequence = "Ctrl-Shift-c";
  #secure_paste_sequence = "Ctrl-Shift-v";
  #windows_count_limit = 500;
  #audio_low_latency = true;
  #log_level = 1;
  #trayicon_mode = "border1";
  #startup_timeout = 45;
};

# most of setting can be set per-VM basis

VM: {
  work: {
    allow_utf8_titles = true;
  };
  video-vm: {
    allow_fullscreen = true;
  };
};

目前支援的設定：

  • allow_fullscreen - 允許 VM 請求其視窗進入全螢幕（沒有彩色邊框）。

    • 注意： 無論此設定如何，您始終可以透過在 Xfce4 中使用受信任的視窗管理器，在視窗標題列上按右鍵並選擇「全螢幕」來將視窗置於全螢幕模式。此功能仍應被視為安全的，因為 VM 視窗仍然無法自願進入全螢幕模式。使用者必須從 dom0 中受信任的視窗管理器選擇此選項。若要從此處退出全螢幕模式，請按下 alt + space 再次叫出標題列選單，然後選擇「離開全螢幕」。

  • allow_utf8_titles - 允許在視窗標題中使用 UTF-8；否則，非 ASCII 字元會被底線取代。

  • secure_copy_sequence 和 secure_paste_sequence - 用於觸發安全複製和貼上的按鍵序列。

  • audio_low_latency - 強制低延遲音訊模式（約 40ms，預設為 200-500ms）。請注意，這會導致 dom0 中 CPU 使用率大幅提高。它預設為啟用，停用它可能可以節省 dom0 中的 CPU。

  • trayicon_mode - 定義系統匣圖示的著色模式。選項有 - bg - 將整個圖示背景設為 VM 顏色 - border1 - 在圖示邊緣新增 1px 邊框 - border2 - 在距離圖示邊緣 1px 處新增 1px 邊框 - tint - 將圖示染色為 VM 顏色，可與其他修飾符一起使用（可啟用多個） - tint+border1,tint+border2 - 與 tint 相同，但同時新增邊框 - tint+saturation50 - 與 tint 相同，但將圖示飽和度降低 50% - tint+whitehack - 與 tint 相同，但將白色像素（0xffffff）改為接近白色（0xfefefe）

  • log level - 定義日誌可以採用的日誌選項。它可以取值 0（僅錯誤）、1（一些基本訊息）和 2（除錯）。

  • startup_timeout - 啟動的超時時間。
