如何貢獻

感謝您有興趣為 Qubes 貢獻心力！以下是一些您可以協助的方式：

  • 稽核來源碼

  • 回報安全性議題

  • 傳送補釘以修復臭蟲或實作功能

  • 貢獻套件

  • 回報臭蟲

  • 測試新版本與更新

  • 提交您硬體的 HCL 報告

  • 錄製影片導覽

  • 建立視覺藝術作品（plymouth 主題、安裝程式主題、桌布等）

  • 撰寫與編輯文件

  • 捐款 給專案

  • 如果您代表組織，請成為 Qubes 合作夥伴

  • 新增 Qubes 下載鏡像站

  • 在郵件列表和論壇上回答問題與討論 Qubes

  • 在社群媒體上與我們互動：

    • 在 Twitter 上追蹤我們

    • 在 Reddit 上加入我們

    • 在 Facebook 上按讚

    • 在 LinkedIn 上與我們聯繫

  • 最後但同樣重要的是，告訴您的朋友和同事 Qubes 如何幫助他們保護數位生活！

貢獻程式碼

如果您有興趣貢獻程式碼，最好的起點是查看我們的 GitHub issues，了解哪些任務最為緊急。您可以根據興趣和經驗篩選議題。例如，以下是一些常見的議題標籤：

  • 徵求協助

  • UX 與可用性

  • Windows 工具

  • 文件

  • 隱私

  • Debian/Ubuntu

在您投入大量時間進行某項活動（例如實作新功能）之前，最好先聯繫我們，最好是透過 qubes-devel 郵件列表。一旦我們討論好細節，我們將感激地 接收您的修補程式。

在貢獻中使用 AI

如果您在貢獻中使用生成式 AI，您必須在提交貢獻時揭露此事。如果您未揭露使用生成式 AI，且審查者有理由相信您已使用，您的貢獻可能會被降低優先級，並可能由審查者酌情決定在未經進一步審查的情況下拒絕。如果您故意且反覆未能揭露使用生成式 AI，且方式對專案或其審查者造成干擾，您可能會被禁止進一步貢獻，或在嚴重情況下，被禁止參與該專案。

所有對 Qubes OS 專案的貢獻都經過人工仔細審查，以評估是否符合專案標準。生成式 AI 讓潛在貢獻者能夠快速且以接近零成本產生大量內容。如果這些貢獻品質高，它們將受到歡迎。然而不幸的是，它們通常品質較低，在這種情況下，即使只有一個 GenAI 輔助的貢獻者，也很容易壓垮整個專案的人工審查能力。

無論您的內容是如何建立的，您都將被視為該內容的完全負責作者，並且您有責任在提交之前審查和修正此類輸出。

此政策適用於您可能貢獻或與專案互動的每一種方式，包括（但不限於）程式碼、修補程式、套件、議題追蹤、回報安全性議題、文件、視覺藝術作品、討論論壇、郵件列表、社群媒體、聊天和電子郵件。

賞金

Qubes OS 專案允許社群成員在 議題 上放置非官方的賞金。這些賞金並非由 Qubes OS 專案官方贊助、認可、保證或支付。提供賞金的個人或團體負責支付賞金，他們決定賞金的價值、支付條款和驗收標準。希望領取賞金的貢獻者應與提供賞金的人協調，以確保他們的工作能成功獲得賞金報酬。

由於賞金是非官方的，重要的是要了解成功的賞金並不一定表示貢獻會被 Qubes OS 專案接受。由於提供賞金的人可以自由設定他們喜歡的任何驗收標準，這些驗收標準可能與 Qubes OS 專案的貢獻驗收標準有顯著差異，這可能導致賞金已支付，但成果之後並未整合到 Qubes 中的情況。這是否是個問題取決於您的目標：有些人對他們可以使用的成果感到滿意，即使它沒有正式整合到專案中，而其他人則不然。如果官方整合對您很重要，您可以讓賞金的支付取決於貢獻是否正式整合到 Qubes 中。

完成賞金議題的貢獻者有時會選擇將賞金捐贈給 Qubes OS 專案，而不是自己領取。在這種情況下，賞金發出者應使用 捐款 頁面上的其中一種方法將賞金發送給專案。
